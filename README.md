# هات پست — h0tpost.ir

سایت اختصاصی هات پست: معرفی خدمات پستی و فروشگاه ملزومات بسته‌بندی و چاپ.

## استک

| لایه | فناوری |
|---|---|
| فریم‌ورک | Next.js 16 (App Router) + React 19 + TypeScript |
| مدیریت محتوا | Payload CMS 3 — داخل همان اپ Next اجرا می‌شود |
| دیتابیس | SQLite (توسعه). برای پروداکشن ← بخش «دیتابیس» |
| استایل | Tailwind CSS v4 |
| فونت | Vazirmatn (SIL OFL)، self-host شده |
| سبد خرید | Zustand + localStorage |

## راه‌اندازی

```bash
npm install
cp .env.example .env      # PAYLOAD_SECRET را پر کنید
npm run seed              # محتوای اولیه از اسناد تیم محتوا
npm run create:admin -- admin@h0tpost.ir "<password>" "مدیر هات پست"
npm run dev
```

- سایت: http://localhost:3000
- پنل مدیریت: http://localhost:3000/admin

## اسکریپت‌ها

| دستور | کار |
|---|---|
| `npm run dev` | سرور توسعه |
| `npm run build` / `npm start` | بیلد و اجرای پروداکشن |
| `npm run seed` | وارد کردن محتوای اولیه (پاک‌کننده — کالکشن‌ها را خالی می‌کند) |
| `npm run create:admin -- <email> <pass> "<name>"` | ساخت کاربر ادمین |
| `npm run import:woo` | گزارش مهاجرت محصولات از ووکامرس (بدون نوشتن) |
| `npm run import:woo -- --apply` | اعمال واقعی مهاجرت |
| `npm run generate:types` | تولید مجدد `src/payload-types.ts` پس از تغییر کالکشن‌ها |
| `npm run generate:importmap` | تولید مجدد import map پنل ادمین |

پس از هر تغییر در `src/collections/` یا `src/globals/` باید `generate:types` را اجرا کنید.

## ساختار

```
src/
  app/(frontend)/     صفحات عمومی سایت
  app/(payload)/      پنل ادمین و REST/GraphQL API
  collections/        محصولات، دسته‌بندی‌ها، خدمات، پرسش‌ها، رسانه، کاربران
  globals/            صفحه اصلی، درباره ما، تنظیمات سایت
  components/         کامپوننت‌های UI
  lib/                کوئری‌ها، سبد خرید، فرمت اعداد فارسی
  hooks/revalidate.ts پاک‌سازی کش پس از ویرایش محتوا
  scripts/            seed، ساخت ادمین، مهاجرت ووکامرس
```

## نکات پیاده‌سازی

**RTL** — کل سایت `dir="rtl"` است. در Tailwind از پراپرتی‌های منطقی استفاده کنید
(`ms-`/`me-`/`ps-`/`pe-`/`start-`/`end-`) نه `ml-`/`mr-`/`left-`/`right-`.

**فونت** — Vazirmatn از پکیج npm برداشته و در `src/fonts/` قرار گرفته و با
`next/font/local` لود می‌شود. عمداً از `next/font/google` استفاده نشده: آن روش
فونت را هنگام **build** دانلود می‌کند و Google Fonts از سرورهای ایرانی قابل
اتکا نیست.

**قیمت‌ها** — به **تومان** و به صورت عدد صحیح ذخیره می‌شوند (مثلاً `13490`).
نمایش با `formatPrice` که ارقام فارسی و جداکننده هزارگان می‌گذارد.

**کش** — صفحات فرانت پیش‌رندر می‌شوند. هوک‌های `src/hooks/revalidate.ts` روی
همه کالکشن‌ها و گلوبال‌ها نصب‌اند و پس از هر ذخیره در پنل، کش را پاک می‌کنند.
این هوک‌ها هنگام اجرای اسکریپت‌های CLI بی‌اثر می‌شوند (کانتکست Next وجود ندارد)؛
یعنی `npm run seed` روی یک سرور در حال اجرا کش را تازه نمی‌کند — بعد از seed
سرور را ری‌استارت کنید.

## دیتابیس

توسعه روی SQLite است (`hotpost.db`). برای پروداکشن اگر Postgres می‌خواهید:

```bash
npm install @payloadcms/db-postgres
```

سپس در `src/payload.config.ts` آداپتر را عوض کنید و `DATABASE_URI` را روی
رشته اتصال Postgres بگذارید. بقیه کد تغییری نمی‌کند.

## مهاجرت از سایت فعلی

سایت فعلی (WordPress + WooCommerce + قالب Woodmart) با API عمومی و
فقط‌خواندنی ممیزی شد. نتیجه: **تقریباً هیچ محتوای واقعی روی آن نیست.**

| مورد | تعداد | وضعیت |
|---|---|---|
| محصولات | ۵ | همه گجت شیائومی — دموی قالب |
| دسته‌بندی محصول | ۳ | جارو رباتیک، ساعت هوشمند، گجت سلامت — دموی قالب |
| صفحات با محتوا | ۴ | متن دمو (درباره ما درباره گوشی شیائومی حرف می‌زند) |
| رسانه | ۸۰ | ۷۴ تا دموی قالب، ۵ تا واقعی |

بنابراین چیزی برای مهاجرت محصولات وجود ندارد. تنها دارایی‌های واقعی این‌ها
بودند که با `npm run import:assets` وارد می‌شوند (بدون نیاز به هیچ رمزی):

- `logo.png` — لوگوی برند → `public/brand/logo.png` (استاتیک)
- `hotpost.png` — تصویر بخش اصلی → `heroImage` صفحه اصلی
- سه آیکون خدمات → پس‌کرایه، تسویه درب منزل، فول‌فیلمنت

> **تصحیح یک ادعای غلط در نسخه قبلی این فایل.** اینجا نوشته شده بود که
> قیمت‌های سایت هزار برابرند و باید بر ۱۰۰۰ تقسیم شوند. این **اشتباه بود**.
> عددِ ۱۳,۴۹۰,۰۰۰ تومان متعلق به جاروبرقی رباتیک Xiaomi X10 Plus است و برای
> آن محصول قیمت درستی است — نه کارتن پستی. اسکرین‌شات سند تیم محتوا از
> حالتی گرفته شده بود که نامِ محصولات دمو را به نام اقلام هات پست عوض کرده
> بودند ولی قیمت‌های دمو سر جایشان مانده بود. اسکریپت `import:woo` که بر
> ۱۰۰۰ تقسیم می‌کرد حذف شد، چون اجرای آن قیمت‌هایی می‌ساخت که *موجه به نظر
> می‌رسند ولی ساختگی‌اند* — و این از عدد آشکارا غلط بدتر است.

قیمت واقعی محصولات باید از کارفرما گرفته و در پنل وارد شود.

## استقرار روی Vercel

> **دسترسی:** Vercel آی‌پی‌های ایران را مسدود می‌کند. بازدیدکننده‌ی داخل ایران
> بدون VPN این دامنه را باز نمی‌کند. برای نمایش به کارفرما با VPN مشکلی نیست،
> ولی **این محیط پروداکشن نهایی نیست** — دامنه `h0tpost.ir` باید روی هاست
> ایرانی بالا بیاید.

سه چیز روی Vercel با نسخه لوکال فرق دارد و هر سه در کد دیده شده‌اند:

| مورد | لوکال | Vercel | چرا |
|---|---|---|---|
| دیتابیس | SQLite | Postgres | فایل‌سیستم Vercel در زمان اجرا فقط‌خواندنی است |
| آپلود فایل | `public/media` | Vercel Blob | همان دلیل |
| ساخت اسکیما | خودکار | migration | Payload در `NODE_ENV=production` اسکیما را push نمی‌کند |

انتخاب آداپتر و استوریج در `src/payload.config.ts` بر اساس وجود متغیر محیطی
انجام می‌شود، پس هیچ سوییچ دستی لازم نیست.

**ترتیب مراحل مهم است.** یک وابستگی حلقوی وجود دارد: بیلد به migration نیاز
دارد، ساخت migration به دیتابیس زنده نیاز دارد، و دیتابیس فقط بعد از ساخته شدن
پروژه در Vercel قابل ایجاد است. `vercel link` این حلقه را باز می‌کند چون پروژه
را بدون دیپلوی می‌سازد. اگر مستقیم `vercel --prod` بزنید، بیلد اول شکست می‌خورد.

### مرحله ۱ — ساخت پروژه بدون دیپلوی

```bash
npx vercel login
npx vercel link
```

### مرحله ۲ — دیتابیس و استوریج

در داشبورد Vercel → Storage، به همین پروژه یک **Postgres** و یک **Blob store**
وصل کنید. Vercel خودش `POSTGRES_URL` و `BLOB_READ_WRITE_TOKEN` را تزریق می‌کند.
اگر Neon جدا می‌سازید، connection string پول‌شده را دستی در Environment
Variables بگذارید.

### مرحله ۳ — دو متغیر دیگر

Settings → Environment Variables:

```
PAYLOAD_SECRET        یک رشته تصادفی جدید (با رشته لوکال یکی نباشد)
NEXT_PUBLIC_SITE_URL  https://<your-project>.vercel.app
```

### مرحله ۴ — ساخت migration (یک‌بار)

قابل رد کردن نیست. `npm run migrate` روی پوشه خالی با کد خروج صفر رد می‌شود،
پس `scripts/preflight.mjs` قبل از بیلد جلویش را می‌گیرد و پیام واضح می‌دهد —
وگرنه بیلد بعداً با خطای نامربوط می‌شکست.

```bash
npx vercel env pull .env.production.local   # connection string را می‌آورد
POSTGRES_URL="$(grep '^POSTGRES_URL' .env.production.local | cut -d= -f2- | tr -d '\"')" \
  npm run migrate:create -- initial

git add src/migrations && git commit -m "Add initial Postgres migration"
```

### مرحله ۵ — پر کردن دیتابیس

قبل از دیپلوی انجامش دهید تا صفحات با محتوا پیش‌رندر شوند:

```bash
export POSTGRES_URL="postgres://..."
npm run migrate                                  # ساخت جداول
npm run seed                                     # محتوای اسناد تیم محتوا
npm run create:admin -- <email> <password> "مدیر"

BLOB_READ_WRITE_TOKEN="vercel_blob_..." npm run import:assets
```

### مرحله ۶ — دیپلوی

```bash
npx vercel --prod
```

اگر بعداً محتوا را از CLI عوض کردید (نه از پنل ادمین)، یک دیپلوی مجدد لازم است:
اسکریپت‌های CLI کش سرور در حال اجرا را پاک نمی‌کنند — بخش «کش» را ببینید.

## استقرار روی هاست ایرانی (پروداکشن نهایی)

برای دامنه اصلی، روی آروان‌کلاد / پارس‌پک / لیارا با Node.js اجرا کنید:

```bash
npm ci && npm run build && npm start
```

اینجا SQLite هم کافی است (متغیر `POSTGRES_URL` را ست نکنید)، ولی `public/media`
و فایل دیتابیس باید بین دیپلوی‌ها روی volume ثابت بمانند.
